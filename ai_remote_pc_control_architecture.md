# AI Remote PC Control — архитектура и план разработки

## 1. Идея проекта

Создать систему, через которую ИИ-агент в терминале (Gemini CLI, Claude Code, Antigravity CLI) может управлять другим твоим ПК: выполнять команды, читать/писать файлы, смотреть экран, управлять мышью и клавиатурой — с подтверждением опасных действий.

Отдельное приложение показывает экран удалённого ПК, чтобы видеть, что именно делает ИИ.

## 3. Компоненты

| Компонент | Технология | Назначение |
|---|---|---|
| MCP Remote Agent | Python, FastMCP | Предоставляет ИИ инструменты для управления ПК |
| Terminal Executor | Python `subprocess` | Безопасное выполнение команд |
| File Tools | Python | Чтение, запись, поиск, удаление файлов |
| Screen Tools | `mss`, Pillow | Скриншоты и просмотр состояния экрана |
| GUI Control | `pyautogui`, `pynput` | Мышь, клавиатура, окна |
| Screen Stream | FastAPI + WebSocket, позже WebRTC | Трансляция экрана в приложение |
| Viewer App | Tauri или Electron | Кнопка «Показать экран», окно просмотра |
| Secure Channel | Tailscale / SSH / WireGuard | Доступ к удалённому ПК без открытых портов |
| Safety Layer | Python | Белые списки, подтверждения, аудит-лог |
| Config | YAML / JSON | Разрешения, пути, порты, токены |

## 4. Режимы доступа

### Read-only
- Просмотр файлов.
- Список процессов.
- Скриншот экрана.
- Чтение логов.

### Safe execute
- Запуск команд из белого списка.
- Создание и редактирование файлов в разрешённых папках.
- Запуск и остановка разрешённых приложений.

### Full control
- Любые команды терминала.
- Управление мышью и клавиатурой.
- Удаление файлов.
- Требует подтверждения пользователя.

## 5. Инструменты MCP

MCP-сервер должен предоставлять такие tools:

```text
ping()
  Проверка соединения с удалённым ПК.

run_command(command, cwd="", timeout=30, require_approval=false)
  Выполнение команды в терминале.

read_file(path)
  Чтение текстового файла.

write_file(path, content, require_approval=false)
  Создание или изменение файла.

list_dir(path)
  Список файлов и папок.

list_processes()
  Список запущенных процессов.

kill_process(pid, require_approval=true)
  Завершение процесса.

screenshot()
  Скриншот текущего экрана.

list_windows()
  Список открытых окон.

focus_window(title)
  Переключение на окно.

click(x, y, button="left", require_approval=true)
  Клик мышью.

type_text(text, require_approval=true)
  Ввод текста.

press_key(key, require_approval=true)
  Нажатие клавиши.

start_screen_stream()
  Запуск трансляции экрана.

stop_screen_stream()
  Остановка трансляции экрана.
```

## 6. Безопасность

Обязательно реализовать:

- Работу только через Tailscale, WireGuard или SSH; не открывать порт в интернет.
- Токен или ключ доступа для MCP-агента.
- Белые и чёрные списки команд.
- Блокировку опасных паттернов: `rm -rf /`, `mkfs`, `dd if=`, `shutdown`, `format`, `sudo rm`.
- Подтверждениеdangerous-действий человеком.
- Полный audit log: время, команда, результат, кто разрешил.
- Ограничение рабочих директорий.
- Автостоп сессии по таймауту.
- Отдельный пользователь ОС с минимальными правами для агента.

## 8. Этапы разработки

### Этап 1 — MVP: удалённые команды
1. Создать Python-проект.
2. Поднять MCP-сервер на удалённом ПК.
3. Реализовать `run_command`, `read_file`, `write_file`, `list_dir`.
4. Добавить белые списки и логирование.
5. Подключить MCP к Gemini CLI.
6. Проверить команду: «покажи список файлов в ~/Downloads и создай test.txt».

### Этап 2 — подключение Claude Code
1. Добавить тот же MCP-сервер в конфиг Claude Code.
2. Проверить одинаковые сценарии.
3. Добавить отдельные системные инструкции для агента.

### Этап 3 — экран
1. Добавить `screenshot()`.
2. Сохранять скриншот во временную папку.
3. Возвращать ИИ путь и краткое описание.
4. Добавить `list_windows()` и `focus_window()`.

### Этап 4 — стрим экрана
1. Поднять FastAPI WebSocket-сервер.
2. Захватывать экран через `mss`.
3. Отправлять JPEG-кадры клиенту.
4. Сделать простую HTML-страницу просмотра.
5. Позже заменить на WebRTC для плавного видео.

### Этап 5 — управление GUI
1. Добавить `click`, `type_text`, `press_key`.
2. Все действия делать только с `require_approval=true`.
3. Добавить окно подтверждения или Telegram-подтверждение.
4. Протестировать на безопасных задачах: открыть браузер, написать текст, закрыть окно.

### Этап 6 — приложение Viewer
1. Сделать Tauri или Electron приложение.
2. Добавить кнопку «Показать экран».
3. Подключить его к WebSocket/WebRTC.
4. Добавить статус подключения, latency и кнопку «Стоп».

### Этап 7 — безопасность и упаковка
1. Настроить Tailscale.
2. Добавить токены и шифрование.
3. Добавить audit log.
4. Написать установщик или скрипт `install.sh`.
5. Протестировать восстановление после обрыва связи.

## 9. Промпт для ИИ-агента: пошаговая реализация

Создай проект поэтапно.

## 10. Первый тест после создания MVP

```bash

cd ai-remote-pc-control/agent
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Затем в Gemini CLI или Claude Code:

```text
Подключись к моему удалённому ПК через MCP.
Покажи список файлов в домашней папке.
Сделай скриншот экрана.
Скажи, какие крупные приложения сейчас открыты.
Не выполняй никаких опасных команд без моего подтверждения.
```

## 11. Чего не делать на старте

- Не давать агенту root/admin-права.
- Не открывать порт напрямую в интернет.
- Не разрешать автозапуск опасных команд.
- Не хранить токены в Git.
- Не делать управление мышью без подтверждения.
- Не начинать сразу с WebRTC: сначала достаточно скриншотов и WebSocket.
